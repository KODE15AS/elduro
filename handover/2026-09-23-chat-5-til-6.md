# Elduro – Handover 5 → 6

**Komplett, selvstendig handover for start av chat 6.** Les denne filen i sin
helhet, deretter [README](../README.md) for arkitektur og filkart. Eldre
overganger ligger i denne katalogen (se Historikk i den levende
[HANDOVER.md](./HANDOVER.md)).

## 0. Hvor står prosjektet nå (kortversjon)

Elduro er et signallaboratorium for Polar H10: live puls, rå EKG (130 Hz) og
akselerometer (200 Hz) via Polars PMD-tjeneste, tapsfri lagring i MariaDB
(delt container, dokumentert unntak i AGENTS.md), ESP32-S3-feltbro over
iPhone-hotspot, web-UI på https://elduro.no (Caddy/Let's Encrypt).

Ved chat-5-slutt: **dual-H10 er operativ på benk.** Belte A strømmer via
ESP32-broen og belte B via BT-600/capture-agenten – samtidig, arbitrert per
belte, arkivert parallelt. Et **syntetisk estimert EKG** (metode 1:
R-topp-forankret klokkejustering + polaritetsjustert fusjon) beregnes live i
backend og vises i den nye **SYNTETISK EKG**-fanen med grunnlag/konfidens og
«washed out» høyrekant. UI-et er finpusset etter Jørns dokument: RAW ECG/ACC
uten kildevelger, automatisk visning av aktive strømmer, stablet A-øverst,
belteregister med BELTE A/B-merking.

## 1. Hva chat 5 leverte (21.09 kveld + 23.09 morgen)

- **Arbitrering per enhet** (`backend/src/main.rs`): kilder låst til ULIKE
  belter via `ELDURO_DEVICE_PINS` (f.eks. `esp32-*=0B052A39,raven:hci1=1DA2053E`,
  `*` = prefiks-match) får strømme samtidig; ellers gjelder fortsatt «nyeste
  start vinner» (19.09-beskyttelsen). Verifisert live: A merket ikke B-startene.
- **Beltefilter i capture-agenten** (`--device 1DA2053E`): skanner matcher kun
  annonseringsnavn som inneholder strengen.
- **PMD stopp-før-start i agenten** (paritet med firmware): rydder foreldreløse
  strømmer efter drept sentral.
- **Hudkontakt/batteri-telemetri fra agenten** (0x2A37-flagg): hvert 5. s og
  umiddelbart ved kontaktendring. (ESP32-firmware har fortsatt 5 s-kadens.)
- **Syntetisk estimert EKG v1** (`backend/src/synth.rs`): per-lane R-topp-
  deteksjon (speiler ecgScope), klokke-fit tA = a + b·tB over matchede topper
  (offset + drift, klemt ±1000 ppm), 50/50-fusjon med polaritetsvakt
  (EMA-korrelasjon), kringkastes som kilde `synth` med
  `{basis, conf, offset_ms, drift_ppm, residual_ms}`. **Genereres kun** -
  arkiveres ikke (beslutning 21.09). Offline-validering:
  `cargo run -p elduro-backend --bin synth_replay -- <fra_ns> <til_ns> <kildeA> <kildeB>`
  mot arkivet. Resultat på ekte dual-data: **100 % R-topp-match, ~3,2 ms
  residual, korrelasjon +0,85–0,94, drift ~−10 ppm.** Valideringsplott:
  `docs/private/2026-09-21-synth-validering.png`.
- **UI-finpuss (Jørns dokument):** RAW ECG/ACC uten kildevelger - viser
  automatisk aktive strømmer, to stablede strimler/paneler (A øverst), ACC
  komprimert til strimmelhøyde med aksene oppå hverandre. RHYTHM/HRV →
  **SYNTETISK EKG** (`/syntetisk-ekg`, gammel path alias). Tachogram (nativ
  grønn vs EKG-derivert rød) og rullende RMSSD består; nativ RR fra ferskeste
  belte (A foretrukket). All tilkoblingsinfo kun på TILKOBLING.
- **Belteregister** (`ELDURO_BELTS=A=0B052A39,B=1DA2053E`, utvidbart med C):
  backend kringkaster `{"t":"belts",...}` ved UI-tilkobling; strimler/kort
  merkes BELTE A/B og sorteres A øverst i RAW ECG, RAW ACC og TILKOBLING.
  NB: ESP32-broens *status* bærer ikke enhetsnavn - UI leser det fra
  telemetrien (hvert 5. s), så merkingen kommer sekunder etter start.
- **Amplitudeforskjell A vs B er fysiologisk, ikke kjedefeil** - verifisert
  med samme belte gjennom begge veier (median 81 vs 75 µV): belte A (øvre
  høyre) har ~30 % lavere R-amplitude enn B (nedre venstre). To avledninger =
  to projeksjoner; dette er selve grunnlaget for syntesen. Behold ærlig
  10 mm/mV - ikke normaliser.

## 2. Driftsregler (benk, dual-H10)

- **Oppstartsrekkefølge fra scratch: belte B (BT-600) FØRST, så ESP32.**
  ESP32-firmwaren mangler beltefilter og tar første belte den ser; når B er
  opptatt (tilkoblet annonserer ikke), kan broen bare finne A. Dokumentert på
  TILKOBLING-fanen. (Permanent fix = firmware-filter, se backlog.)
- Beltepark: **A** = 0B052A39 (app-fw 3.3.1, stabil referanse, IKKE oppdater),
  *øvre belte, senter ~5 cm under høyre brystvorte*. **B** = 1DA2053E
  (app-fw 4.2.0), *nedre belte, rotert, senter ~8 cm under venstre
  brystvorte*. **C** = reserve, antatt lik B. Plassering skal logges som
  øktmetadata (backlog).
- Agent på verten:
  `nohup ./bin/elduro-capture --backend ws://127.0.0.1:8094/ws/agent --agent raven --device 1DA2053E >> agent.log 2>&1 &`
  (OBS: `pkill -f elduro-capture` dreper eget skall - bruk `pkill -x`.)
- `.env` (gitignorert) har `ELDURO_DB_URL`, `ELDURO_SUBJECT_ID`,
  `ELDURO_DEVICE_PINS`, `ELDURO_BELTS`.
- **Backend-omstart (deploy) nullstiller `wanted`-kartet:** BT-600-økten må
  STARTes på nytt; ESP32 strømmer videre av seg selv.
- **Belte-reset (knappcelle ut) sletter beltets bindingsnøkler** → PMD feiler
  med «Not paired»/«Not connected». Fix: `bluetoothctl remove <MAC>` på hci1
  (BT-600 = kontroller B0:82:E2:1F:9C:2D) og par på nytt manuelt med
  `bluetoothctl pair` (btleplug har ingen paringsagent). Belte B MAC:
  24:AC:AC:1D:A2:05.
- Foreldreløs PMD-strøm etter drept sentral ryddes nå automatisk
  (stopp-før-start), men fysisk pause (puck av stroppen 30-45 s) kan fortsatt
  trengs ved fastlåst belte; ekte reset = knappcelle ut.
- 12-avlednings-referansen (11.09.2026, Østl. Hjertesenter Moss: sinus 60,
  PQ 237 ms, QRS 88 ms, QTc 420 ms, stor negativ T V3-V6, negativ T V2)
  ligger som `docs/private/2026-09-11-ekg-12-pkt.jpg` (gitignorert -
  helsedata committes aldri).
- H10-oppvarming 5-35 s; DIS-fw ≠ app-fw; RSSI-krav −85 dBm (BT-600-veien
  trenger nærhet til raven).
